# TOP26006_fw repository registry

This is the stable project role and ownership registry for the TOP-26-006 coordination workspace. `TOP26006_fw` is the single project and agentic governance owner. Its local checkout remains `/users/apiccine/work/correction-lib`; the checkout name is not the project identity. Each listed Git repository retains its own history, index, branch state, native technical policy, and remote authorization boundary. A path is a location contract, not proof of a live Git ref or permission to write.

For a task governed from the TOP26006_fw coordination checkout, select the repository by `repository_id`, read root `AGENTS.md`, `CPC.md` when constructing a prompt, root `CONTRIBUTING.md` for reviewer prose, the applicable named module, and every path-applicable nested `AGENTS.md`. The module adds project-specific constraints and cannot weaken root safety or create authorization. Effective actions must satisfy both TOP26006_fw project operational governance and applicable upstream/repository-native policy. Resolve branch, HEAD, tree, dirty state, remote identity and advertised refs freshly when decision-material; none is durable semantic registry truth. A configured remote never implies publication permission.

## Ownership contract

| Contract | Owner |
|---|---|
| Project operational branch, mutation, evidence and publication governance | `TOP26006_fw`, through root governance and the applicable module |
| Project prompt and agentic contract | `TOP26006_fw`, through root `CPC.md` and the applicable module |
| Upstream repository policy | The repository or its upstream project; it remains independently applicable |
| Scientific and technical content | The applicable repository-native scientific/technical or domain semantic authority; current task assignment is resolved externally by the TOP-26-006 control plane |

The project default for every non-coordination repository is read-only unless the exact round separately grants repository, path, and effect write scope. Module-specific defaults can be stricter. A project write grant does not override an upstream restriction or permit a remote action. This registry records durable semantic ownership, not current control-plane task assignments.
