# Autonomy and blocker classification

Load for autonomous or adaptive execution, blocker classification, preauthorized
fallback or repair, continuation after a mechanism failure, or an
anti-artificial-blocker decision. This contract classifies findings within
existing authority. It grants no effect, changes no acceptance boundary, and
does not override an explicit owner instruction or a stricter applicable rule.

## Hard-stop test

Do not create or preserve a hard blocker unless continuing within current
authorization can produce or select a wrong result, perform an unauthorized
effect, irreversibly lose decision-material state, adopt or overwrite foreign
work, cross a new owner, scientific, or governance decision boundary, act on
insufficiently bound identity, continue after an unsafe ambiguous outcome, or
violate an explicit owner boundary.

Before stopping or continuing, answer these questions against current evidence:

1. What exact wrong, unsafe, unauthorized, or irrecoverable consequence could
   continuing cause?
2. Which authoritative rule or owner decision establishes that boundary?
3. Is the concern an invariant or only a selected mechanism?
4. Is an equivalent or predeclared fallback already authorized and invariant
   preserving?
5. Is the missing evidence needed for this decision or only for a stronger
   later claim?
6. Is a superseded or already satisfied gate being recreated?
7. Can valid completed state be preserved while only the affected delta is
   repaired?
8. Did an effect have an ambiguous outcome that requires readback before retry?

If no concrete authority or safety consequence exists, do not invent a hard
blocker. A warning alone is not a blocker; it still requires relevance and
disposition. A finding does not authorize automatic continuation.

## Classification vocabulary

Use the following labels for stop-like conditions and findings. They are not
CPC permission keys or workflow stage states and create no authority.

| Label | Current-decision disposition |
|---|---|
| `REAL_AUTHORITY_OR_SAFETY_BOUNDARY` | Stop the dependent effect until exact authority or safety evidence exists. |
| `REAL_IDENTITY_OR_RESULT_BOUNDARY` | Stop the dependent selection or claim until the required identity or result is bound. |
| `OUTCOME_UNKNOWN` | Observe the effect and its state before retry or recovery. |
| `AUTHORING_DEFECT` | Stop the defective prompt or effect; assess actual impact on work already done. |
| `MECHANISM_OR_CAPABILITY_LIMITATION` | Use an already-authorized equivalent if all invariants hold; otherwise stop only the dependent action. |
| `EXPECTED_ABSENCE_OR_FALLBACK_BRANCH` | Follow the declared fallback and its gates. |
| `EVIDENCE_OR_PROVENANCE_LIMIT` | Lower only the claim that needs the missing evidence. |
| `NONBLOCKING_FINDING` | Record and disposition without blocking the current decision. |
| `FUTURE_PHASE_LIMIT` | Retain for the future phase; do not convert it into current-stage failure. |
| `SUPERSEDED_GATE` | Do not revive a gate displaced by authoritative current policy or accepted closure. |

Classify from the concrete current consequence, not from the wording of a
warning, tool failure, or prompt. A terminal process is not proof of a
successful result. Cleanup status is not semantic success. Lint PASS is not
authorization. Exact byte union is composition identity, not semantic
correctness.

## Autonomous adaptation

An agent may adapt execution without owner reapproval only while all of these
remain invariant: semantic objective, repository identity, authorized read and
write surfaces, scientific assumptions, effect envelope, validation ceiling,
acceptance boundary, foreign-work preservation, and remote, production, and
publication prohibitions. Applicable scheduler boundaries remain binding.

Minimum sufficient alternatives include an equivalent maintained or local
command, a predeclared fallback, continuation that preserves completed state,
bounded readback after an ambiguous outcome, a bounded safe base rebind, and
skipping checks_not_to_repeat. Each alternative must retain its own required
identity, evidence, grants, and objective gate. Readback does not itself
authorize retry. A changed master OID alone does not invalidate a continuation
when the declared source and dependency boundary is unchanged.

Adaptation cannot invent repository or write scope, a refactor, new science, a
wider claim, remote, production, scheduler, or publication effects, destructive
cleanup, foreign-work adoption, or a different unbound result identity. It
cannot waive a real stop boundary to keep a workflow moving.

## Authoring and review

When applicable, prompts bind accepted_prior_evidence,
accepted_closure_layers, invalidation_boundary, delta_scope,
unresolved_checks_only, and checks_not_to_repeat using existing CPC fields.
State invariants, selected mechanisms, preauthorized fallbacks, and real stop
boundaries separately. A proposed hard stop identifies its concrete consequence
and authoritative source. A mechanism inconvenience is not a hard gate when an
already-authorized invariant-preserving alternative exists.

Reviewers classify a prompt defect by its actual impact, including after
execution; they do not automatically annul or replay otherwise valid results.
Missing evidence for a stronger claim does not invalidate a supported current
result. Future-phase gaps stay future. Preserve valid completed effects and
repair only an authorized delta; new substantive choices stop under the owning
contract. Historical pilot or cleanup mechanics are examples, never new
universal gates.
