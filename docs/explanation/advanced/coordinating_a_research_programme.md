# Coordinating a research programme

Larger research questions may need separate methods, checking, and explanation responsibilities. A useful workstream has a bounded question, output, input identity, reviewer, and acceptance route. A coordinator can make dependencies and handoffs visible so people know which result is ready and which remains blocked.

Serial work is preferable when a later method cannot be defined until an earlier result is accepted, when the same mutable surface lacks a safe partition, or when coordination cost exceeds the independent work available. More workers or agents do not make a result more credible. Quality comes from declared methods, evidence, independent checks with stated limitations, review, and owner acceptance.

The [three-workstream teaching case](../../examples/advanced_parallel_workstreams/README.md) shows a raw-listing check that can proceed independently of an estimate's changing assumption, while a methods note must wait for an accepted estimate. The coordinator records that gate; the scientific owner retains acceptance authority. A workstream is a responsibility boundary and may use one human, several bounded tasks, or no AI tool at all.
