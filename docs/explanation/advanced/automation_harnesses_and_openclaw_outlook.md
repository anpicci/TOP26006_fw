# Automation harnesses and OpenClaw: an outlook

This is a dated documentary outlook based on the owner-accepted `FW_DOCS_ADVANCED_RESEARCH_006A_REPORT_20261024_R1` and its adversarial review, cutoff **2026-10-24**. The mechanisms below were **NOT LOCALLY TESTED** in TOP26006_fw. OpenClaw is an evaluated candidate example, not an adopted TOP26006_fw dependency. No multi-agent or harness mechanism was locally qualified by 006A or this manual.

The project still defines responsibility, dependency identity, review, acceptance, invalidation, and transfer. Provider traces, transcripts, trajectories, and backups can supplement project records; none is complete scientific provenance. Workspace, session, state, and tool separation must not be treated as hard security isolation.

| Level | Problem addressed | Evidence gained or lost | Trust, maintenance, and recovery burden | Human control and proof before adoption |
| --- | --- | --- | --- | --- |
| 0 — human-supervised documented exchanges | Coordinate bounded tasks and explicit decisions. | Parent-owned records show inputs, review, acceptance, and continuation; manual omissions remain possible. | Smallest automation footprint; people inspect stopped or uncertain effects. | Owner authorizes tasks and accepts exact evidence; test record completeness on a synthetic case. |
| 1 — small parent-owned helpers | Check references or routine record consistency. | Repeatable mechanical checks help catch missing edges but cannot make scientific decisions. | Helper code, failures, and outputs need an owner and maintenance contract. | Human reviews exceptions and acceptance; prove a helper's scope and failure behavior before use. |
| 2 — provider-native agents or teams | Delegate bounded subtasks or exchange results within a provider surface. | Provider logs may show execution and messages, but delivery or completion is not acceptance. | Effective permissions, context, tools, and write collisions require surface-specific qualification. | Human task authority and review remain; qualify the exact provider surface, settings, and evidence behavior locally before operational use. |
| 3 — persistent harness such as OpenClaw | Retain coordination state across sessions and support bounded continuation. | Trajectories and backups may aid diagnosis, with redaction or omission limits; they do not reproduce a scientific execution. | Persistent services, plugins, trust domain, external effects, and recovery procedures enlarge operational burden. | Human owns authority and acceptance; require threat-model, permission, effect, restart, and restore tests for the intended installation. |

The accepted 006A research distinguishes **ChatGPT Work subagents**, **local Codex subagents/custom agents**, **Agents API multi-agent**, and **Responses API multi-agent**. They are different documented surfaces, not one interface or permission contract. It also distinguishes **Claude Code subagents** from **Claude Code agent teams**; the latter were documented as experimental and default-off at the 006A cutoff. All are `NOT LOCALLY TESTED` here. A separate agent or session alone does not establish independent review, and parallel conversations do not make simultaneous writes safe.

For OpenClaw, the accepted 006A boundary is one trusted operator/team per Gateway. An agent workspace is not a hard sandbox; a session key is not an authorization token; cross-session visibility can exist inside the trust domain; plugins run as trusted Gateway code. A trajectory is bounded and redacted diagnostic evidence. Backup and restore do not reproduce the old scientific execution. OpenClaw documents retained completion handoffs and bounded post-restart reconciliation/continuation mechanisms; interrupted commands are not automatically replayed. These are documented claims at the cutoff, **NOT LOCALLY TESTED** for this project, and no installation or deployment path is approved here.
