# Why the research method can travel while provider controls differ

**Explanation; documentation snapshot: 2026-10-23.** A research task begins with a question, purpose, method, provenance, evidence, review, and a human acceptance boundary. Those responsibilities can be described without naming an AI product. The [research workflow](research_workflow.md) and [roles](roles_and_authority.md) assign them to people and project functions.

Four layers should stay distinct. **Research method** says what a claim requires. **Project governance** says who may authorize work, which repository owns it, and when a result may be accepted. **Provider mechanisms** load instructions, ask before actions, restrict tools, and retain or lose context. **Local installation** supplies actual versions, settings, paths, and observed behavior. A portable method is a reusable structure for decisions and evidence; it is not a promise that different providers load, restrict, review, or remember work identically.

The 2026-10-23 official-document comparison gives concrete reasons. Codex describes a root-to-working-directory `AGENTS.md` chain with override and fallback behavior. Claude Code documents conditional direct `AGENTS.md` reading from v2.1.277; `CLAUDE.md`, `.claude/CLAUDE.md`, and a private `CLAUDE.local.md` can change the default selection. Nested material may load at different times, including on-demand path rules. The same text in an instruction file may therefore reach different sessions, or fail to reach one. [Codex instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md) and [Claude memory](https://code.claude.com/docs/en/memory) describe their respective mechanisms.

Permission vocabularies and enforcement also differ. Codex's current local sandbox and approval names do not map by name to Claude's permission modes or allow/ask/deny rules. Claude's optional Bash sandbox covers shell commands and children; its built-in file tools, hooks, and MCP paths need separate examination. A prompt can authorize less than a runtime technically permits. Conversely, a prompt cannot make an unavailable sandbox exist. See the [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference), [Claude permission modes](https://code.claude.com/docs/en/permission-modes), and [Claude sandbox](https://code.claude.com/docs/en/sandboxing).

A provider's permission prompt, hook, or code review addresses actions or code. It does not decide whether a statistical model fits a data set, whether provenance is adequate, or whether the owner accepts an interpretation. The [evidence and acceptance boundary](evidence_reproducibility_and_acceptance.md) remains a project and human responsibility across providers.

The [compatibility matrix](../reference/provider_compatibility.md) states documentary status; the [adaptation guide](../how_to/adapt_to_another_ai_provider.md) turns these distinctions into a local qualification sequence.
