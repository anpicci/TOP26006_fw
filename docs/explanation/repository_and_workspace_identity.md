# Repository and workspace identity

A repository has its own history and rules. The [repository registry](../../governance/repositories.md) records durable roles, while a [local profile](../reference/local_profile.md) maps those roles to installation paths. A directory name or remote alias identifies neither the current revision nor permission to change it. A live ref readback is needed when its target matters.

A branch or ref names a movable position in a repository's history. A working tree holds checked-out files, and its index holds the proposed next snapshot. The exact base revision identifies the starting content and history for a task; the exact candidate revision identifies the result proposed for review or later use. A branch name alone cannot stand in for either revision. Path agreement and a checked-out branch do not authorize a change: the repository's rules and explicit permission for the path and action still apply.

Separate working trees can isolate checkout and index state for independent writers. They are optional, and their separation does not prove that the work is semantically independent or that its combined result is correct. A worker-produced frozen result, with its base and evidence, is distinct from the candidate assembled by a coordinating step. The assembled candidate may contain multiple results and new interactions. Neither temporary result is the same as permanent development state, whose branch and authority must be handled separately.

Byte-for-byte comparison can prove which result was assembled and preserve provenance. It cannot prove that newly combined behavior or interfaces are correct. Review the assembled candidate and validate affected interactions at the boundary where they will be used. The [evidence review guide](../how_to/review_returned_evidence.md) gives the corresponding procedure.
