# Define workstream responsibilities

Use this when a research question has more than one bounded stream of work. Start with the scientific owner and existing governance; a [workstream record](../../reference/advanced/workstream_record.md) documents an assignment but cannot grant it.

1. State the question, method or evidence need, exact scope, exclusions, and stop boundary for each stream. Keep a single stream if the proposed split has no independently useful output.
2. Name the responsible researcher or role and, separately, the executor if someone or something else performs a task. A provider session is not a responsibility owner.
3. Pin source material and dependency revisions. Give outputs stable IDs, and say which downstream claim may use each output.
4. Bound permitted effects, including repositories, files, external jobs, and data movement under the actual task authorization. A record does not broaden that authorization.
5. Name the independent review route and the scientific or project acceptance route. Record who can stop work when an input, authority, or method assumption changes.
6. Connect the workstream to the [coordination history](../../reference/advanced/coordination_record.md) and test the fields against the [synthetic example](../../examples/advanced_parallel_workstreams/workstreams.md).

Recheck the assignment when a method, source, reviewer, or responsible person changes. Record the authority reference and handoff before treating a new receiver as responsible.
