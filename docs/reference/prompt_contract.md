# Prompt contract

The authoritative field contract is defined in [CPC.md — Construction](../../CPC.md#construction) and its [Conditional field router](../../CPC.md#conditional-field-router) with execution constraints in [AGENTS.md](../../AGENTS.md). A dispatchable prompt states one **decision_question**; prompt ID, title, mode, model/reasoning/delegation choice; repository locations and allowed/read-only surfaces; the applicable outer or stage branch policy and validation ceiling; effect permissions; evidence, stop, patch, and final-report contract as applicable.

For a non-orchestrated actionable prompt, outer `branch_policy` is required and outer `heavy_command_permissions` carries positive grants. For `orchestrated_workflow`, both outer fields are prohibited: each branch-relevant stage declares `stage_branch_policy`, and `stage_effect_permissions` carries that stage's positive grants. The outer `workflow_effect_envelope` is only a ceiling. Use the current [CPC construction rules](../../CPC.md#construction) and [orchestration contract](../../governance/contracts/orchestration.md#stage-delta-contract) for exact fields and constraints.

A continuation identifies accepted prior evidence, delta, invalidation boundary, and checks not to repeat when those carry real state. An orchestrated workflow declares ordered stages and a stop policy. Field presence and mechanical validation do not prove authorization from the research lead or scientific adequacy. [Manual writing](../how_to/write_a_prompt_manually.md) is for an author who can check the live contract; [validator use](../how_to/validate_a_prompt_before_execution.md) is a separate mechanical check.
