# Tutorial 9: transfer work to a collaborator

**Learning goal:** create a handoff from which a successor can recover accepted evidence, residual work, and the next authorized decision.

Use the [handoff template](../../templates/handoff.md) and the [observed scenario](../../examples/research_workflow_lifecycle/observed_scenario.md). Its owner/reviewer entries are simulated for teaching.

1. Name the scientific owner of interpretation and the separate prompt author, executor, and reviewer roles. The new collaborator receives information, not automatic scientific or repository authority.
2. Record the illustrative accepted scope: synthetic arithmetic under independent Gaussian uncertainty, analysis scratch commit `c9f7c6b9e090fdc3ae3c29b34171cf3a7cb88ff4`, and the methods evidence commit `09a97e3ced516e662a8e448f01b9199805c3ea80`. Cite the CSV hash, wrapper output, and simulated review. Mark the first analysis note's provenance wording as superseded.
3. Record residual mandate: decide ownership and disposition of the unexpected `interpretation.md` edit; real-data method and publication remain unexamined. Name the invalidation boundary: input, method, relevant commit, or live task-scope state changes. Do not repeat accepted arithmetic unless that boundary is crossed.
4. Ask the successor to read the cited artifacts and confirm comprehension, then obtain any new authorization before work. The transfer record itself is evidence for continuity, not proof that the recipient understands it.

**Checkpoint:** another researcher can locate authority, accepted result, provenance, superseded wording, stop, and next decision without oral context. Return to the [manual index](../index.md) for bounded how-to and reference material.
